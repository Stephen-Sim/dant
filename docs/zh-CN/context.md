# 上下文与 token 管理

[English](../context.md) · Chinese

## 由 Codex 管理上下文策略

dant 的文字任务和原生订阅语音任务复用当前会话的 Codex 线程。配置模型的上下文窗口、token 计量和自动压缩由 Codex 管理；dant 不设置 `model_context_window`、`model_auto_compact_token_limit`、最大输出 token 或自定义截断策略。

重新连接恢复同一个线程。编辑、删除或清空可见聊天记录不会重置模型会话，也不会根据界面记录重建一份缩短后的模型历史。Codex 与模型仍可按原有策略进行压缩；这不代表上游模型的窗口变为无限。

正常挂断音频不会替换会话，也不会取消已经确认接收的任务。后台任务保留同一个 turn，完成后将结果发到聊天；后续文字和通话仍通过原会话读取这些结果。显式停止工作、执行器错误及无法确认的任务归属仍采用各自的中断规则。

## 语音与文字共享会话

两个语音入口都使用共享身份／工作笔记及最新的带作用域记忆参考。原生通话保留 Codex 自身的线程历史、启动摘要与上下文默认策略。独立 API 入口从当前已保存聊天构建带角色标记的参考，包括附件名称和表情；读取这些参考不打开、恢复或验证 Codex 订阅线程。历史请求只作数据参考，不再次执行。清空可见聊天会改变后续 API 通话可用的参考，但保留 Codex 线程。两种服务的历史与上下文窗口并不相同。

通话中，不带附件的文字只进入当前语音会话一次；引用回复会携带原消息的完整内容与实际说话者。语音直接回应，需要执行时沿用该通道的后台委派流程，不再同时启动普通文字任务。订阅通话中已完成的语音暂存在当前通话内；原生语音历史由 Codex 通过委派及通话结束时的转写写入负责，保留口头信息且不增加转写气泡。关闭或替换通话会丢弃临时语音快照。

通话中的文字也以不可执行的参考写入同一个 Codex 线程。由于公开线程投影不返回原始注入条目，私有 `callInputHistory` 保存完整脱敏文字、引用角色与内容、归属和提交状态。这些记录在可见历史改变或应用重启后保留线程上下文；API 通话的初始聊天投影不读取这份私有记录。它不进入桌面状态快照，也不是另一项任务或自动保存的偏好。未确认的提交不会自动重放。

可选 API 语音通过只写参考的 `thread/inject_items` 把已完成的用户和助手语音提供给同一个 Codex 线程，不启动模型任务。由于 Codex 的聊天历史投影不会返回原始注入条目，私有 `voiceHistory` 字段另存这些已完成的参考，保留线程连续性；它不进入 API 通话的初始聊天投影、桌面状态快照、Telegram 聊天或可见消息。输入转写按服务方条目 ID 排序，排除取消、未完成与带外助手输出；文字任务等待前面的语音上下文确认。注入结果未知时不自动重试。

保存持久记忆会刷新当前语音会话与后台线程。API 语音收到回执后替换旧记忆快照；已完成的文字回复也同步为实时参考。语音上下文不会自动写成持久偏好，仍需明确调用 `memory_write`。API 转写在现有 WebRTC 与旁路连接上使用 `gpt-transcribe`，仍需单独配置 API Key。

## 持久记忆与人格

持久笔记与保留的项目上下文由 SQLite 保存，通过 Go [`memory.Store`](../../core/internal/memory/store.go) 和 revision 缓存访问。`identity.md` / `working-memory.md` 保留为兼容视图，迁移后的 Markdown 文件是显式导入导出快照。Agent 基础记忆上下文只使用这些安全笔记；包含最新 32 条确认条目的上下文视图保留用于兼容/只读展示，不会整批自动加入 Agent prompt。

已经准入的输入即将发送时，`memory.Store.Retrieve` 从当前请求或选中的未完成任务提取字面 OR 关键词，进行有界的本地 FTS5 召回。共享笔记与符合条件的确认事实在排序前按对话/工作作用域过滤，项目记忆必须匹配选中的工作 ID。普通轮次、任务调整、自动续作、识别后的音频、原生/API 通话文字及 API 语音任务委派都使用这条路径，不增加另一项推理请求。匹配摘录有大小限制、脱敏并保留来源；无匹配时原输入不变。修改、删除和冲突变化在发送前重新读取。

召回文字只作为当前输入的参考，不是新的用户指令、权限或恢复其他工作的依据。它不修改保存的用户消息，不另加持久注入，也不清除 Codex 旧历史；提供商历史中已有的摘录仍可能保留，因此包装明确限定作用范围，并在当前输入中取代旧摘录。空闲 heartbeat 不进行召回。详见[记忆架构](architecture.md#memory存储缓存与召回)。

会话历史与持久记忆是两种独立来源。**记忆与人格**页保留固定的 `DANT_IDENTITY_INSTRUCTIONS` 为只读内容，通过搜索与分页列表管理 SQLite 中的权威共享文档和结构化事实／经历。逻辑文档 ID 不是文件位置，来源和项目引用会保留显示；列表内容少，不代表模型会话已被清空。

连接后的管理界面可编辑或清空文档，编辑或删除结构化记录，并明确确认审核后的候选记忆。编辑事实会将其返回候选状态。写入核对捕获的数据库修订，经过脱敏的记录禁止覆盖隐藏原文。离线副本保持只读；状态过期或写入结果未确认时，须先重新读取权威状态。这些操作不会发送模型输入或启动任务，详见[记忆设置](settings.md)。

模型仍可通过 `memory_write` 保存参考笔记，但 dant 目前不会在每条消息、每次通话或任务完成后自动提取和整理笔记。已保存的笔记可影响后续回应，固定身份指令则不是单独学习得到的人格档案。刷新记忆只会重新读取已保存内容，不会生成新笔记。

## 完整内容提供给模型

- 文字消息、编辑、任务调整及通话任务不再受 dant 原有的 100,000 字符输入上限限制；保存编辑与明确重新发送仍保持各自原有行为。
- 实时通话参考包含完整消息、引用消息或表情目标文字；这些内容只作参考，当前用户输入只向语音会话交付一次供其回应。
- 安全的身份/工作笔记和已启用技能描述不再按原有的 12,000/16,000 字符预算截断；补充召回摘录另有固定大小与数量限制，不截短用户输入，凭据脱敏仍保留。
- 可选 API 语音接收完整传入的聊天历史及实时参考更新，不再按 16 条或 32 KiB 删除旧更新，也不设置服务方的 token/截断选项。
- API 语音任务结果独立于有上限的界面输出收集；最终内容替换流式片段，只有任务确认完成后才返回完整脱敏结果。取消或提交不确定时，不把部分结果当成成功。

补充的消息 ID 和表情查找快照使用简短标签，用于定位反馈，不代替 Codex 线程中已有的原始输入。文件名也不代表已读取附件内容。

## 观察和存储边界

界面与语音适配器也会消费协议通知，这些重复观察副本与模型上下文独立。已知、仅用于通知的大结果可缩小为元数据，包括 Codex 序列化的截图文本预览；模型的原始工具结果保留。实际 RPC 请求、交付结果、任务归属及停止控制仍会校验。

语音观察队列的 1 MiB 上限、请求体大小、附件限制及记忆单文件 64 KiB 上限属于传输或存储边界，不是模型 token 预算。故障元数据见[诊断日志](diagnostics.md)，数据归属见[架构](architecture.md)，自动测试与真实设备验证范围见[验证记录](verification.md)。

[用量统计设置](settings.md#token-用量)只记录并展示服务方返回的实际消耗，不改变模型上下文窗口、自动压缩、输出上限或计费，也不估算未提供的语音用量。
