# 诊断日志与保留期限

[English](../diagnostics.md) · Chinese

dant 在 Windows Controller 和 Ubuntu Worker 上分别记录结构化诊断。内容包括连接和任务状态、超时类别、通话关闭原因、标识符、计数和耗时；不包含对话正文、截图像素、文件内容、请求头或凭据值。

默认**最多保留 3 天**，每日轮换，**单文件上限 5 MiB、总量上限 50 MiB**。启动时及运行期间定时清理；达到大小限制时，旧文件可能提前移除。日志写入失败不会中断应用。

定时清理每小时执行。旧版 Windows 启动日志 `data/startup.log` 单独使用首行保留时间标记管理，避免再次启动延长旧内容的存活时间。没有标记的旧文件首次接管时清空一次；达到 3 天，或检查时超过 1 MiB，就在原文件上截断并写入新时间标记，保留启动器已打开的追加写入句柄。

日志位置：

- Windows：`%APPDATA%\com.dant.desktop\data\logs`
- Ubuntu Worker：`~/dant/data/logs`

通过已鉴权的 `GET /api/diagnostics` 可读取有限条最近诊断和保留配置。Controller 在 Worker 可达时附带其报告；VM 断开时仍能读取本机诊断。不要上传整个应用数据目录，其中还包含个人对话和连接资料。

保留配置中的版本表示当前日志记录器的版本，每条记录仍保留实际写入它的版本。当前记录器正常但尚未写入新事件时，最近记录仍可能来自旧版本。Worker 会分别记录服务启动和首次执行器连接的结果；Telegram 轮询在这次连接尝试结束后才启动，避免启动时积压的消息与任务接收的维护窗口竞争。

Telegram 输入失败使用固定诊断码和当前语言的提示，分别区分队列容量、附件传输、持久化、任务接收、取消和超时。任务接收诊断还会区分执行器不可用、归属变化、执行状态未确认和背压。日志不包含消息正文、机器人令牌或底层错误原文。旧记录中合并的“附件或队列”提示无法确定最初失败的具体操作。已有失败消息保持原样，代码更新不会自动重试；结果不确定的提交继续遵守原有确认要求。

服务更新诊断使用固定状态、更新阶段、检查步骤及原因码，并保留经过校验的目标版本和运行版本，可区分暂停或空闲检查失败、连接失败及激活未确认，包括 `pause-unconfirmed`、`idle-unconfirmed`。记录不包含 SSH 原文、安装路径或任务内容；界面显示简短的当前语言提示，不展示整段安装输出。

执行器断线记录保留最先观察到的原因，例如输入流结束、读写失败、协议帧无效或过大、事件背压及请求超时。无法分类的失败保留为 `unknown`，不推断成读取错误；后续进程退出不能覆盖最先观察到的原因。观察到进程结果时，同一记录还包含退出码、信号、dant 是否请求停止及进程是否已停止，不记录进程 stderr 或协议帧正文。传输失败后发出的停止请求不能证明最初断线的原因。明确关闭和已过期的连接代次不会产生意外断线记录。缺少退出证据时仍标记未确认；仅凭执行器离线，不能推断 VM 崩溃、内核重启或内存不足终止。

当观察者消费较慢时，同一 thread、turn 和消息的相邻文本片段会在交付前合并，减少重复写入聊天历史。合并不丢弃文本，也不会越过完成事件、工具请求或归属变化。持久化追赶期间，传输读取仍能处理 RPC 响应。每个观察者保留 64 项事件上限，并限制为 64 MiB 有效载荷预算；无法合并的真实过载仍以 `event-overflow` 断开连接。关闭订阅时按顺序保留已接收的事件，不等待已停止消费的一方。

桌面端通过经过认证的原生 API 刷新聊天状态。可见消息的回执提交成功后，会等待当前状态快照确认，避免 VM 刷新较慢时反复写入回执，导致状态快照持续被判定过期。消息 DOM 节点替换时保留回执归属；切换聊天或电脑会使排队的旧回执失效，迟到的回复也不能清除同一消息的新请求。只有前台且未最小化窗口中的可见消息会开始生成回执。

任务准入保留触发安全暂停的原因，区分用户明确暂停、人工接管、执行器断线及提交或继续未确认。停止期间收到新消息，不会把原暂停原因改写为 `user-paused`。明确暂停或继续可以改变这项状态，但重连或更新应用不会自动重试未知工作。缺少这些证据的历史记录无法确定最初原因。

## 桌面消失不一定是 VM 崩溃

VM、桌面桥和 Codex 执行器是独立组件。VM 可能正常运行，但执行器已停止。此时 Computer 面板继续提供只读预览，只显示一行连接状态和 **Reconnect（刷新连接）**。请求进行时显示**连接中**并阻止重复点击，不另加第二条离线提示或独立刷新按钮。重连不会自动重放暂停的任务；新的电脑输入仍受执行器和归属检查限制。

桌面刷新会等浏览器完整加载并解码图片后才替换画面；失败、超时或过期的帧会保留上一张正常画面，并提示重试。收到新的正常 VM 状态后会清除旧连接错误，仅有缓存状态不会清除。客户端在响应完成前断开时，日志记录状态 `499` 和原因 `client-aborted`，内容仅含路由、方法与耗时。取消一次预览请求不能证明 VM 已停止。

通话关闭诊断会区分缓冲上限、未跟踪的交接、未确认的提交和未确认的停止。任务归属或停止状态不明确时，dant 可能终止旧执行器，防止后台工作继续运行；这不会关闭 VM。

较大的工具结果仍完整提供给模型。语音观察队列只为不需要消费的大结果保留有上限的元数据，覆盖截图 JSON 文本预览、命令输出和生成媒体；正常 MCP 图片的重复字节也会省略。聊天交付结果、RPC 请求、归属信息及停止控制仍保留原有校验和预算。`voice_observer_image_omitted` 和 `voice_observer_payload_omitted` 只记录原始及保留大小、固定的项目类型和状态，不记录输出内容。真正的控制事件及未知协议结构仍受 1 MiB 上限保护。

反馈故障时，请提供大致本地时间、当时是否在通话、可见状态和相关结构化记录。内核重启或 OOM 证据需另行检查，执行器离线本身不能证明这两类故障。
