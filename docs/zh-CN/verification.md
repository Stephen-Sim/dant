# 验证与验收

[English](../verification.md) · Chinese

验收分为源码检查、产物完整性和真实设备行为三层。单元测试通过不能证明某个安装包、VM 更新、麦克风或外部交付可用。证据必须对应准确源码和产物；候选变化后，先前候选的结果不能算作新版本通过。

## 源码检查

按[测试](testing.md)和 [CI](ci.md) 执行完整命令，使用固定工具链和隔离夹具。记录源码提交、平台、工具版本、命令结果、覆盖计数及平台专用排除。缺少前置工具或进程失败仍是失败，不能复用过期报告或降低门槛。

- Go 检查覆盖全部功能包、vet、格式及规定的语句覆盖率；Linux 另运行 race。
- 浏览器／工具检查覆盖严格 TypeScript、生成契约、状态域、递归测试和 UI 覆盖率。
- Rust 测试覆盖原生行为，并独立进行 LLVM 插桩；Python 测行／分支弧，PowerShell 通过 Pester 测可执行命令。Bash 使用固定版本的 Linux kcov、隔离夹具和全部维护脚本清单；语法检查或夹具通过不能替代覆盖率。平台前提缺失时须报告为不可用。这些检查都不能操作真实 VM。
- 构建和版本检查校验清单一致、依赖锁、干净源码来源和已准备资源。

每种覆盖率分别记录源码范围、已覆盖／总数、平台和工具链。TypeScript 百分比不能代表 Go、Rust 或 Python，测试数量也不能替代插桩覆盖率。插桩缺失或失败时应记为不可用，不能推断成 100%。向接近 100% 改进时持续记录未覆盖维护文件和平台缺口，保留现有门禁，不隐藏未测脚本；保留同一源码的 CI 摘要和可下载原始报告。

行为证据与布局检查分开记录。浏览器夹具使用实际渲染器和样式表，返回合成数据，验证宽／窄布局、键盘控制及相关文字方向。应用状态不可用时，恢复页面也必须可用。

## 候选产物

安装前核对标签、提交、版本和 Windows 构建元数据属于同一候选，要求相关 CI 任务通过，包括 Linux race。校验 `SHA256SUMS`、资源长度、元数据及全部打包清单；不得替换已发布产物。

便携版的 `dant.exe` 与完整 `backend/` 目录必须一起保留。校验 Windows Core、Linux Worker、固定辅助文件、前端和来源清单。安装包与便携版原生程序的 PE 资源可能不同，必须与实际提供该文件的产物比较。

使用普通私有暂存位置，拒绝变化文件、链接、不安全归档路径、重复条目及字节不符。保留已有数据和备份。校验和通过本身不授予停止任务、修改 VM 或发布版本的权限。

## 桌面验收

1. 保存草稿并使用受支持的保护退出／更新流程，确认执行暂停及预期 VM 生命周期结果。替换文件前确认已安装的原生进程和 Controller 均退出；静默安装器不是正常退出接口。
2. 按受支持路径安装已验证候选，首次启动前校验安装版本及预期资源哈希。单独分类残留文件，不能为了校验通过而删除用户数据或无关资源。
3. 只启动一次；读取本机会话但不暴露令牌，要求 `product=dant`、`mode=controller`、`runtime=go`、`protocol=1` 及准确候选版本／源码。
4. 确认实际聊天能够渲染，包括仅附件和空文本记录。私下比较对话／消息／任务身份及暂停／未知屏障，不能只比较数量。
5. 验证设置、离线恢复、Work progress、已读／未读、文件预览／下载和托盘生命周期。在不改动无关用户设置的前提下验证原生通话悬浮窗和编辑器偏好。

## Worker 部署与数据恢复

使用准确配置的 VM 身份及已验证的 SSH 主机密钥；显式维护期间保持自动部署暂停。调整资源或关闭 VM 前，要求单独授权的备份、离线状态和所有权检查。新建 VM 默认 4 CPU、8 GiB 内存、64 GiB 磁盘，不得静默缩小已有规格。

替换 Worker 前，确认维护准入、服务／执行器进程停止、各文件系统暂存空间足够，且具有完整认证备份。保留部分归档和原安装日志作为证据，不能把部分归档标记为可用备份。

离线准备和激活必须绑定准确尝试、源码、bundle、根目录及备份。核对 committed 日志、准备证明和已部署源码，再确认实际 Worker 会话的 `mode=worker`、`runtime=go`、`protocol=1` 及准确目标版本／源码。脚本成功退出或桌面缓存状态均不足以代表完成。

恢复检查涵盖对话身份、目标根目录下经验证的附件字节、技能内容、SQLite 记忆／调度、暂停工作和保留的不确定结果。恢复不得重放未完成任务或计划交付；受支持的早期数据格式仍保留兼容校验和备份。参见 [Go Core](go-core.md)和[备份](backups.md)。

## 实际功能

真实检查要求已授权的账号和设备范围，不能成为单元测试副作用。

| 功能           | 证据                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| 聊天与任务执行 | 单执行准入、保留任务身份／上下文、暂停／取消，以及有实际意义的完成或阻塞报告。 |
| 语音           | 输入／输出设备、通话状态、文字／通话共享上下文、挂断后任务继续和当前通话字幕。 |
| 电脑           | 新截图、稳定显示、所属输入／接管和安全归还。                                   |
| 文件与 Skills  | 正确字节／名称、不跳转的预览／下载、完整 ZIP 导入导出和已配置编辑器行为。      |
| Telegram       | 明确所有者配对、新消息／附件交付与回执，不重发历史未确认交付。                 |
| 备份与恢复     | 完整认证归档、独立目标校验、字节保留和恢复后不自动执行。                       |

## 验收记录

说明执行了什么、准确源码／产物／平台及实际结果。源码测试、打包启动和真实功能检查分栏记录。诊断仅包含有界固定错误码、布尔、数量和耗时；公共报告不包含令牌、账号标识、用户正文、私有路径或原始进程输出。

即使全部源码门禁通过，未完成的真实检查仍为待验收。发布或安装另一候选需要它自身的产物身份和验收证据。
