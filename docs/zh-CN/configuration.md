# 本地配置

[English](../configuration.md) · Chinese

将仓库根目录的 [`.env.example`](../../.env.example) 复制为 `.env`。开发启动器与 Vite 在启动编译后的 Go Controller 前读取它；已有的进程环境变量优先。`.env` 及私有变体由 Git 忽略，也不会进入 VM 归档或桌面安装资源。

| 变量              | 默认值      | 用途                  |
| ----------------- | ----------- | --------------------- |
| `DANT_HOST`       | `127.0.0.1` | 本地开发 API 地址。   |
| `DANT_PORT`       | `4317`      | 本地开发 API 端口。   |
| `DANT_DEV_PORT`   | `4318`      | Vite 开发端口。       |
| `DANT_GUEST_HOST` | `127.0.0.1` | VM 图形桌面桥接地址。 |
| `DANT_GUEST_PORT` | `4320`      | VM 图形桌面桥接端口。 |

地址只接受 `127.0.0.1` 或 `localhost`，端口必须是 1 至 65535 的整数；部署的 guest 端口不得与 VM API 或引导桥端口相同。无效配置会明确报错，不会悄悄改回默认值。Go [`config`](../../core/internal/config/network.go) 负责运行端点与 VM 部署设置的校验；[`scripts/config`](../../scripts/config/network.mts) 只校验构建／开发端点。健康检查、截图和操作地址使用运行端点配置。

原生桌面 IPC 与 SSH 转发的 VM API 保持固定端口 `4317`，它们属于协议常量，不受开发端口设置影响。部署时，清单只传递两项公开的 guest 设置，并同时写入 worker 与 guest 服务；修改这些设置会改变部署指纹，`.env` 本身不会被复制。凭据继续通过已有的受保护设置保存。

## 配置归属

| 类别                     | 来源                             | 规则                                                                                 |
| ------------------------ | -------------------------------- | ------------------------------------------------------------------------------------ |
| 开发及公开部署参数       | 由所属配置边界读取 `.env`        | 组装服务前统一校验；已有进程环境优先。                                               |
| 用户偏好                 | 现有 Settings 存储与鉴权设置 API | 语言、外观、备份模式和间隔仍由用户设置管理。                                         |
| 共享原生传输协议         | `resources/config/protocol.json` | Go、Rust、Python、浏览器及工具共用同一组回环端点和路由来源。                         |
| 新电脑的资源默认值与范围 | `resources/config/computer.json` | 创建表单和 Go、PowerShell、Python 启动器共用；用户显式选择优先，现有电脑保留原规格。 |
| 固定协议与安全上限       | 所属功能中的命名常量             | 授权规则、字节上限、路由白名单和执行归属不能通过环境变量改写。                       |

`npm run generate:contracts` 更新 Go 内嵌协议及 Tauri 配置的网络字段；`npm run check:contracts` 拒绝生成结果漂移。Rust 读取内嵌的规范协议，Python 的 `vm/network_config.py` 对源码目录、种子镜像及已安装辅助程序读取同一协议并校验。种子镜像包含该资源，引导与就绪检查共用 guest 端点，不再各写一个端口。Go 部署器内嵌首次连接检查所需的 Python 源码，显式传入已校验的原生端点和路由，因此尚未安装辅助程序时也能检查。

规范协议要求固定主回环地址、精确回环白名单、互异合法端口，以及有界、互异的根路径；重复 JSON 字段、未知键和无效值均被拒绝。修改共享协议值属于源码／构建契约变更，与调整开发 `.env` 参数分开。Tauri 开发窗口使用生成的规范开发端点，独立运行的 Vite 使用 `DANT_DEV_PORT`。

新电脑默认使用 4 核、8GiB 内存和 64GiB 磁盘，每种资源在统一文件中定义 `default`、`min`、`max`，创建前校验用户选择。这些默认值不会触发已有 VM 扩缩容；种子描述也不能代替运行中 VM 的实际规格证据。

种子镜像的系统服务使用统一配置中的 `bootstrapGuestPort`（`4319`），安装后的用户桌面桥默认使用 `guestPort`（`4320`）。两者共用控制租约并分别监听，安装 Worker 无须停止系统服务的权限。引导就绪检查使用引导端点；部署后的 Worker 检查使用配置的 guest 端点。`scripts/check-vm.ps1` 只验证初始种子服务，不能代替部署后 Worker 验收。

配置、领域枚举和安全常量的区别见[代码规范](code-style.md)。

安装版不需要 `.env`，缺少该文件时使用内置默认配置；`.env.example` 只是模板，不会作为运行时后备文件读取。

SSH 通过命名协议常量默认使用 `22`，每个已保存的电脑连接仍可在设置中选择自己的 SSH 端口。API 和 Vite 的环境端口不会改动该连接设置。

`DANT_DATA` 与 `DANT_WORKSPACE_ROOT` 可选择明确的存储位置，对应 Go 启动参数优先；不设置时动态解析正常用户路径。原生宿主在启动时只捕获一次 `DANT_DATA`。改路径不会搬运现有数据或恢复备份；数据转移仍使用正式备份与恢复流程。

## Worker 数据

部署后 Worker 的默认数据根目录为 `~/dant/data/`。下表路径相对于其配置的数据目录；这些是私有运行数据，不是仓库文件或 `.env` 设置。

| 路径                         | 数据权威                                 |
| ---------------------------- | ---------------------------------------- |
| `state.json`                 | 聊天消息、持久任务及已读/交付/提交回执。 |
| `memory/dant/memory.sqlite`  | 持久笔记、确认记忆及保留的项目上下文。   |
| `schedules/schedules.sqlite` | 调度、创建请求删除记录及派发屏障。       |

旧调度只导入一次，备份保存在调度数据库旁。记忆 Markdown 文件在迁移后仅作显式导入导出快照。不要用旧 JSON/Markdown 副本覆盖更新的数据库，详见[持久化与恢复](architecture.md#数据与生命周期)。
