# 工作电脑备份

[English](../backups.md) · Chinese

在 **设置 → 聊天与数据 → 工作电脑备份** 中保存 VM 的 dant 持久数据。恢复始终需要先预览，再明确点击 **替换数据并恢复**。本文描述当前源码；已发布安装包可能仍是较早的实现。

备份设置、已保存副本和便携导出放在 **聊天与数据**。独立的 **导入备份文件** 卡片保留在 **工作电脑**，方便配置电脑时导入已有的 dant。导出会选择一份已保存的备份，VM 离线时也能操作；列表为空时须先创建备份。

## 配置备份

| 设置           | 行为                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 手动           | 只有 **立即备份** 会创建副本；定期、连接后、更换 VM 前的自动触发全部关闭。                       |
| 自动           | 启用选中的连接/更换 VM 触发项与定期备份，默认采用此模式。                                        |
| 备份间隔       | **15–10,080 分钟**，默认 **60 分钟**。                                                           |
| 连接后         | 默认开启，符合条件的连接会安排后台备份检查。                                                     |
| 更换工作电脑前 | 默认开启，需要先完成备份，再进行连接或配置变更。                                                 |
| 保留数量       | 默认 **每台工作电脑保留 10 份**；鉴权设置 API 还接受 `retainCount` 1–100，当前界面未提供此控件。 |

Controller 负责配置与后台检查。设置页面只读取元数据、提交明确动作，不会运行 Agent、发送 heartbeat 聊天汇报或增加模型请求。离开设置页面会停止该页面的轮询，Controller 仍可完成已接纳的备份。

备份要求工作电脑连接正常、Worker 支持备份，且本机秘密保护可用。只要 Worker 能安全导出空闲数据，模型提供商可以尚未登录。正在执行的工作、通话、用户接管、安装或其他受保护操作可能阻止捕获。捕获被拒绝或发现来源变化时，已有备份会保留。

开启 **更换工作电脑前备份** 后，首次变更请求可能启动备份并返回 `backup_before_vm_change_required`。等待备份完成，再明确重试原来的变更操作；Controller 不会把切换 VM 延迟排队。近期成功的副本可以满足此保护。手动模式会关闭该保护及其他自动触发项。

## 存储与覆盖范围

配置位于 Controller 现有私有数据目录的 `dataDir/backup-settings.json`，归档位于 `dataDir/vm-backups/<id>.dantbak`。目前不提供自定义目的地，也不回退到明文保存。保留策略按来源电脑分别计算，新电脑的备份不会挤掉旧电脑应保留的副本。

每份本机归档使用独立的 **AES-256-GCM** 密钥，并由 Windows **DPAPI** 使用本地用户配置保护密钥；归档元数据与密文一起参与认证。迁移到另一账号或电脑时，使用**导出备份**生成密码保护的便携 `.dant` 文件；只复制私有 `.dantbak` 文件不会迁移本机密钥。宿主秘密保护是明确的能力边界：未来 Unix 适配器需要先实现该能力，才能启用本地备份。没有可用实现时会明确失败，不会保存未加密归档。

新版归档只包含 **agent 数据**，不会打包整台电脑或整个工作区。data 域包含聊天/任务历史和设置（`state.json`）、记忆（`memory/dant/`）、调度、已保存的聊天附件，以及本机集成/凭据状态。workspace 域只包含 `<conversation>/.agents/skills/` 和 `<conversation>/.dant-disabled-skills/` 中的托管 Skill 库，保留 PNG 等二进制资源。其他工作区内容不参与遍历：浏览器资料、虚拟环境、仓库、项目文件、依赖、构建产物和缓存都不包含在内。Skill 库中的运行环境和缓存目录也被排除。

已经保存为聊天附件或交付文件快照的内容会保留。仅存在于工作区的文件或输出链接不等于已保存的附件；需要依靠备份转移时，请先把文件保存到聊天。上述 agent 数据根目录之外的 Codex 登录资料和原生会话缓存不参与捕获。恢复归档中包含的 Skill 库会替换该库，因此库内被排除的环境和缓存需要重新创建。这不是操作系统或 VM 磁盘镜像。

捕获会暂存普通文件，限制读取大小并核对文件身份和版本。Worker 的 **data** 目录中的 SQLite 数据库（包括记忆与调度）通过 **`VACUUM INTO`** 与完整性检查生成快照，不把正在使用的 journal/WAL 边车文件当成独立数据复制。data 数据库被锁定或无效时会拒绝捕获。

接受捕获前会重新检查所有已纳入文件和目录；纳入范围内的来源发生变化时会中止捕获。整个归档**不是全系统 ACID 事务**，不会冻结其他外部进程。捕获/恢复暂存采用私有目录并清理，只有完整加密归档会成为保留副本。空间预估与捕获使用相同的选择规则，不计算被排除的工作区目录。

新版明文归档使用 `DANT-BACKUP/2`、schema version 2 和明确的 `agent-data` 范围。未知范围和范围外条目在修改实时数据前被拒绝。版本 1 归档仍可读取，并保留原来的 data/workspace 完整替换语义；新范围不会自动缩小已有备份。旧应用会拒绝版本 2，不会把部分工作区误当作完整替换。纳入目录中的符号链接、硬链接和特殊文件会明确拒绝，不会跟随。

Go 服务所有权文件 `.dant-core-owner.lock` 属于运行状态，不参与捕获或便携导出；恢复也不会把该锁转移到新数据根目录。Linux 离线恢复、恢复核对和导出除了持有替换目录之外的持久内核恢复锁，还会取得 Go 所有权锁，因此另外运行的 Go Worker 会阻止这些操作。systemd 服务必须确认已经停止，且 cgroup 中没有剩余进程；停止结果未知时，不会替换数据。

Go 实现保留原有本机和便携 AES-GCM 字节格式。短时运行的 `--role=backup-transform` 子进程只对独占创建的私有暂存文件建立文件映射，并使用标准库 AEAD 加密或认证；解密认证成功之后才提供明文读取。密钥通过有大小限制的 stdin 传递，不进入命令参数或日志；取消会终止并等待该子进程退出。这避免 Controller 分配与归档大小相当的 Go 堆内存。映射页仍会占用子进程驻留内存，捕获与导入/导出也需要私有临时磁盘空间，包括明文暂存；完成或失败后会清理暂存。隔离的 256 MiB 测试覆盖加密和解密两个方向，只记录子进程堆与驻留内存峰值；它验证内存边界，不承诺性能。

## 明确选择恢复

目标 VM 可以使用不同的 Linux 用户名和 home 目录。归档目录域恢复到目标的 data、workspace 根目录；记忆和调度数据库从这些目录打开，托管 Skill 路径由当前工作区生成。准备模型输入前，Engine 会按不变的附件 ID 从目标 AttachmentStore 解析并校验实际字节，不会回退使用另一台 VM 保存的路径。附件缺失或内容变化时，不会启动该轮执行。用户编写的文本、脚本及其中的绝对路径保持原样，不作替换。

首次使用时，dant 会先询问是否已有备份。有备份可以先导入，没有再创建工作电脑。导入不要求 VM 在线，也不会恢复或启动任务；之后连接或创建目标 VM，再预览导入的备份并恢复。

通过**导出备份**，可以在支持的客户端、电脑和 VM 之间迁移或分享 dant。输入并确认密码，保存便携文件；在目标电脑选择**导入备份**，选中文件并输入密码。Controller 会先验证密码认证和归档结构，再以目标电脑的本机保护方式保存。密码错误、文件被篡改或上传中断，不会成为成功导入。Windows 文件选择器采用流式处理大文件；浏览器备用传输限制为 64 MiB。

便携导出保留所选范围内的身份、记忆、Skills、聊天/任务历史、调度和已保存的附件；排除已知凭据库、模型/SSH 登录资料及集成密钥，目标电脑需要重新登录或配对。备份包含个人聊天和记忆，请只分享给预期接收者。导出和导入都会保留经过认证的归档范围。本版提供明确的文件导入/导出，不连接 Drive。

便携过滤还会排除旧版归档中的私有 `.env` 变体和 Git 远程配置（`.git/config`）。这些旧归档仍可能包含项目文件和 Git 对象；新版在捕获时就排除项目与 Git 目录。认证过滤依据目录域和明确路径，不猜测任意文件内容。

1. 连接目标工作电脑，打开备份列表。
2. 点击 **预览恢复**，核对时间、服务版本、文件数量与大小。预览会提示来源电脑或版本不同，以及当前数据将被替换。
3. 只对该预览点击 **替换数据并恢复**。取消、过期、刷新、更换电脑/对话、离开页面或断开连接，都会废弃界面的确认。服务端也把短时、单次确认绑定到准确备份与目标连接。
4. 等待结果。`202 {started:true}` 只表示操作已接纳，不表示已经完成；界面通过元数据轮询确认结束。

Controller 会先暂停工作并确认静止，再停止 `dant-worker.service`，通过 SSH 运行固定的恢复 CLI；VM 保持开机。CLI 在私有暂存目录校验完整归档。agent 数据恢复只替换 data 根目录和归档中明确存在的托管 Skill 库；归档中没有的库保持原样。现有 workspace、对话目录和 `.agents` 父目录保留身份，无关的浏览器资料、虚拟环境和项目文件不受影响。持久组件 journal 支持中断后的回滚和恢复，不会重放归档。旧版版本 1 仍保留原来的双根目录替换语义；两种事务都不是跨文件系统的一次原子重命名。Worker 重启后，Controller 会核对准确的启动时恢复回执，才报告成功。

恢复保留历史 ID 和结果，移除正在使用的执行/线程绑定。非终态任务保持暂停；已有不确定提交保持不确定，不会重放。调度任务被禁用/暂停，已派发历史和派发屏障保留，未完成交接需要核对。恢复后 Telegram 被禁用。模型登录资料不包含在归档中，可能需要重新登录。恢复数据不会悄悄继续任务、周期作业或发送消息。

恢复中断或结果未确认时，会保留持久回执并显示未知结果。检查先核对启动时已加载的回执。如果数据已经确认提交、但服务尚未启动，固定 CLI 会在持有 Linux 内核恢复锁期间核对准确的恢复 ID 和当前服务状态，之后才完成启动。它不会重新上传、应用或回滚归档。提交记录缺失或结果不确定时仍保持阻挡。先核对实际状态，再考虑新的恢复或更换 VM。

Controller 提供 `GET /api/backups`、`PATCH /api/backups/settings`、`POST /api/backups/run`、`POST /api/backups/import`、`POST /api/backups/:id/export`、`POST /api/backups/:id/preview` 和 `POST /api/backups/:id/restore`，沿用本机 API 鉴权。Worker 的导出与回执接口仍通过已鉴权的 VM 通道访问。备份接口不会让 Windows Controller 成为 Agent 执行器。

测试使用隔离数据、注入的通信与时钟，不会备份、恢复、停止或重连用户的真实 VM。相关边界和验收记录参见[系统架构](architecture.md)、[VM 设置](VM.md)和[验证](verification.md)。
