# Telegram 接入

[English](../TELEGRAM.md) · Chinese

Telegram 网关在 Ubuntu VM 内运行，与桌面共用持续对话和串行任务引擎，默认关闭。VM 在线时，关闭 Windows 窗口后仍能收消息。VM 需要能访问 Telegram 的 HTTPS 接口，不需要开放公网入站端口。

## 连接机器人

1. 打开官方 [@BotFather](https://t.me/BotFather)，用 `/newbot` 创建机器人并复制 Bot Token，参见[官方教程](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)。
2. 让 dant 连接已有 VM，在“设置 → Telegram”中把 Token 填入密码框并启用。不要把 Token 发到 dant 聊天、源码或 issue。
3. 生成配对链接，用你自己的 Telegram 私聊打开链接并点击 Start。一次性配对码十分钟后过期，成功后设置应显示已配对账号。
4. 向机器人发中文或英文消息。符合限制的图片、文档和音频附件会进入同一条对话；语音在 VM 内本地识别后供共享模型线程内部使用，两端保留原始语音。桌面发送的新消息和 dant 完成的回复也会出现在这条私聊中。

只允许一个私聊账号配对，用户 ID 和聊天 ID 必须同时匹配。群聊、频道及其他账号不能仅凭机器人用户名提交任务。配对链接在使用前应保密。

## 命令和消息交付

- `/help`：显示可用命令。
- `/status`：查看共享执行器、通话、当前工作和队列状态。
- `/progress`（也支持 `/porgress`）：查看与桌面工作进度相同的当前及最近工作，包括已登记标题、步骤状态和任务 ID。
- `/pause`：请求确认停止当前共享工作，并暂停排队任务，语音通话保持连接。
- `/resume <task-id>`：使用 `/progress` 中的完整任务 ID，明确继续已知的暂停或失败消息任务。不带 ID 时只会选择唯一符合条件的暂停任务；多个候选须明确指定 ID。
- `/stop`：请求停止来自本 Telegram 连接的活动任务；不能停止无关的桌面任务或订阅通话。

这些命令只对已配对的私聊账号开放。`/pause` 控制共享工作，也包括从桌面或通话交办的任务；`/stop` 仍只控制本 Telegram 的任务。命令不会重建对话或创建另一个执行器，步骤勾选也不会覆盖真实任务状态。

继续任务不会绕过提交结果未知、已有活动任务、执行器离线、人工接管或订阅通话限制，须先处理提示的情况。仅通过口述交办的任务没有可恢复的用户消息任务 ID，请在聊天或原已接通通话中重新明确交代。

普通消息遵循与桌面相同的交互投递、队列、人工接管租约及通话限制。当前已确认任务能接收补充时，消息直接送给它；通话中的文字交给同一语音会话回应。计划任务及明确恢复保留各自队列行为。普通聊天不建工作条目；相关工作跨轮次接续原任务 ID，未完成计划保持**进行中**，完整计划才进入待验收。发送到 Telegram 不等于用户验收。群聊不创建工作。

附件会进行内容识别，单文件最大 10 MiB。不支持的格式或超限下载会明确失败。外发文件只能来自应用已经归档的不可变附件，不能任意上传 VM 路径。

## 两端共用一条对话

桌面和已配对 Telegram 私聊共用 VM 内的对话、上下文、附件和串行任务队列。Telegram 指令只创建一个任务，桌面也能看到；不会把同一条用户消息再回传到 Telegram。桌面发送的消息由机器人加上 **You · desktop** 前缀转发，Telegram 中显示的发送者仍是机器人。

dant 新完成的消息和附件都会同步，无论任务从桌面还是 Telegram 发起，也包括通话中明确交付到聊天的消息和文件。流式生成片段和实时通话音频不转发。长文本拆分为 Telegram 支持的纯文本消息。

同步从配对时开始；已有配对在首次升级到支持聊天镜像的版本时开始。不会批量回灌已有历史，重启 VM 也不会重发这些历史。编辑、删除、清空历史、引用回复关联和 reaction 暂不在两端同步；清空桌面历史也不会重建模型会话。

重复更新使用稳定输入 ID 去重，不会重复执行。重启后不会自动恢复被中断的模型任务。

外发请求即使响应丢失，也可能已经到达 Telegram。这类交付标为“结果未知”，不会盲目重发；重复操作前先检查 Telegram。明确失败也会保留在网关状态中。

## 凭据和解绑

Token 经已有认证 SSH 连接传入 VM，保存在 VM 用户数据目录的单独受限文件中，不写入聊天状态、记忆、Windows 展示缓存、浏览器存储、日志或 Git。状态接口只返回配置和配对状态，不回显 Token。

停用会终止轮询。解绑会删除配对账号，移除 Token 会清除已保存凭据。更换 Token 会重置配对和轮询状态，避免新机器人继承旧账号权限。授权其他账号时生成新的配对链接。

## 排障

已有 webhook 会阻止长轮询，dant 会提示冲突，不会擅自删除其他应用的 webhook。可以另建一个机器人，或明确移除旧 webhook 后重连。[Bot API 文档](https://core.telegram.org/bots/api#getupdates)说明了这一限制。

同一个 Bot 同时有另一个轮询客户端也会冲突，应只运行一个网关。网络报错时检查 VM 是否能访问 Telegram。停用 Telegram 不删除 VM 聊天或文件。

自动测试使用模拟 Bot API、隔离数据和注入任务引擎。真实 Telegram 端到端验收需要你自己的 Token 和配对，CI 不使用真实 Telegram 账号或密钥。
