# Repository instructions

Read [docs/code-style.md](docs/code-style.md) before changing this repository. These rules apply to source, tests, scripts, native code, and documentation.

## Structure and ownership

- Put backend runtime packages in the matching feature directory under `core/internal/`, browser modules under `ui/`, and build/development tooling under `scripts/`. Keep `core/cmd/` entrypoints small. Do not recreate the retired root `src/` backend or move it into test support.
- Put adopted Go core packages under `core/internal/<feature>/` and every Go test under the mirrored `tests/go/<package>/` directory. Use the shared Go test runner's explicit compiler overlay to retain private package coverage; do not export production internals for tests. Keep browser, Node, Controller, Worker and native boundaries unchanged until a feature explicitly migrates through its validated contract.
- Keep Go entrypoints small and interfaces narrow, defined by the consuming feature. Pass `context.Context` first through blocking operations, preserve cancellation and use `errors.Is`/`errors.As` for classified failures. Give goroutines explicit owners, limits and joined shutdown. Use parameterized SQL, validated typed DTOs and explicit nullable values; avoid generic `BaseRepository` or unrelated `common`/`utils` abstractions.
- Keep the browser, Windows Controller, Ubuntu Worker, and Tauri native host separate. The Controller must not create a task Engine or execute agent work on Windows. Cross a boundary through its existing authenticated API, IPC command, or validated transport.
- Keep dependency direction explicit. Shared contracts must not import a browser entrypoint, the Controller entrypoint, or the Worker entrypoint. Avoid circular imports and generic utility folders for unrelated features.
- On a module move, update imports, resource allowlists, tests, coverage discovery, scripts, and documentation together. Preserve persisted file names and public API routes unless the change explicitly includes a migration.
- Mirror browser ownership in `tests/ui/<module>/` and build/development tooling in `tests/tooling/<module>/`. Go tests belong under `tests/go/`, native boundary tests under `tests/native/`, and Python VM tests under `tests/vm/`. Shared fixtures belong in `tests/support/` and compile-time contracts in `tests/types/`. Keep test discovery recursive; do not add test files to the root of `tests/` or beside tooling source.

## Code and configuration

- Use the repository's pinned Prettier and Rust formatter. Run `npm run format` after editing supported files, then `npm run format:check`. Do not hand-format generated files, add ignore directives to bypass a failure, or disable the CI formatting gates.
- Use exactly Go **1.27.2** and its matching `gofmt` for the Go core. Use the shared `scripts/core/go.mts` runner, which rejects other toolchains and sets `GOTOOLCHAIN=local`; never silently use an older PATH tool or let a check download another compiler. Go formatting uses tabs; TypeScript remains strict and keeps its existing formatter and type gates.
- Use UTF-8, LF, spaces, and final newlines as defined in `.editorconfig`. Python and PowerShell use four-space indentation; keep their existing syntax checks and behavioral tests. Do not add a formatter that is not declared and reproducible in this repository.
- Read deployment and local development options through the shared configuration module. Validate environment values once at the configuration boundary. Use named constants for protocol limits, fixed allowlists, error codes, and security invariants; these are not user-tunable environment options.
- Never commit `.env`, credentials, tokens, private keys, real account identifiers, runtime state, or logs. `.env.example` contains documented non-secret examples and empty placeholders only. Never expose secret values in diagnostics or errors.
- Use the shared language registry for supported codes, locale metadata, and language validation. Reuse the localization layer for interface and fixed system text. Preserve placeholders, counts, and keyboard accessibility. Do not translate user messages, task titles, project memory, file contents, or other user-provided content.

## State and side effects

- Define shared state domains in `resources/contracts/state-domains.json`. Use generated Go constants under `core/internal/contracts` and frozen TypeScript domains in `ui/shared/states.mts`, with stable string wire values. Keep task, submission, continuation, connection, update, runtime OS and spoken-reference states distinct. Validate unknown external values before accepting them; never coerce an unknown value into success or a safe retry.
- Keep cross-runtime schemas under `resources/contracts/`, protocol defaults under `resources/config/`, and language data under `resources/i18n/`. Browser wire types live in `ui/shared/api-types.ts`; feature-specific types stay beside their owning modules. All backend packages use Go; browser code, tools, and Node tests use strict TypeScript checked by `npm run typecheck`. Node tooling uses `.mts` with erasable types and the declared Node 22.18+ LTS / 24+ baseline; pure type files use `.ts` and type-only imports. Do not use `any`, suppression directives, disabled strictness, unchecked JSON assignments, runtime TypeScript enums, decorators or transform-dependent syntax to conceal migration errors. Validate disk and transport data at the owning boundary and preserve supported legacy omissions without inventing identities or timestamps. Extend the adopted scopes in `scripts/ci/check-state-contracts.mts` and run `npm run check:states` for new state-owning features; its Go AST and UI AST checks must remain enabled.
- Use `npm run generate:contracts` to update generated Go/TypeScript contracts and embedded protocol data, and `npm run check:contracts` to verify them. Do not edit generated vocabulary independently. Preserve wire identities and uncertainty semantics across languages.
- Preserve exact task, turn, conversation, and connection identity across asynchronous operations. Check that the captured identity is still current before applying a result.
- Do not automatically retry a task or external action whose outcome is unknown. Reconcile its actual state first; retain an explicit unknown result when confirmation is unavailable.
- Keep durable task state separate from an execution turn. Closing a window, ending a call, or an ended response must not mark unfinished work complete. Explicit pause, cancellation, input blockers, and human control must continue to stop automatic execution.
- Diagnostics record bounded, validated operational metadata. They must not copy user content, credentials, raw request bodies, or arbitrary process output.

## Verification

- Add or update behavioral tests for changed contracts and meaningful failure paths. Avoid tests that merely reproduce implementation details; prefer public outputs, persisted state, and bounded side effects.
- Run relevant tests while working. Before handing off an integrated change, run `npm run format:check`, `npm run typecheck`, `npm run check:states`, `npm run test:coverage`, the Python VM-helper suite, `node scripts/ci/preflight.mts`, `pwsh -File scripts/ci/check-powershell.ps1`, `node scripts/ci/version.mts`, and `npm run build`. Run native tests when changing Rust behavior. Report unavailable prerequisites and actual failures; do not describe unrun checks as passing.
- Also run `npm run check:contracts`, `npm run check:core`, and `npm run test:core:parity` for the adopted Go core. The dedicated core CI checks formatting, vet, tests and isolated memory parity on Windows and Linux, and runs the race detector on Linux with its required C compiler. Go tests use isolated fixtures and must not reconnect a VM, contact a real model or operate user data.
- Keep CI formatting, coverage, version, syntax, and release-integrity checks enabled. Fix failures at their source; do not lower thresholds, remove required modules, or skip required checks to make a change pass.
- `npm run check:core` runs all Go package tests with statement coverage. Controller, Computer (including discovery and transport), and Telegram each require at least 90%; every maintained feature package must appear. UI coverage retains 90% lines, 80% branches and 80% functions, with appearance individually at 90% lines. Go statement percentages and Node line percentages are different metrics; report them separately. Keep the frozen synthetic Node oracle provenance for Memory differential tests without retaining an executable Node backend.
- Use isolated fixtures for tests. Do not start real model sessions, reconnect a user's VM, send Telegram messages, use the microphone, or install an application as a side effect of a test.
- Keep English and Chinese developer documentation consistent when changing a documented workflow. Releases must retain matching manifest and lockfile versions, verified assets, and their source provenance. Do not replace assets on a published release.
